02 / The engineering choice

Local by default.
Online only when requested.

Local analysis is the default. Online lookups are opt-in. Passwords are masked in display and exported results, with hidden-prompt or stdin input.

Online checks send specific data to third parties. See Implementation & limits for what leaves the device.

03 / The workflow
  1. Provide input

    Hidden prompt or stdin.

  2. Analyze locally

    Pattern checks and hash identification.

  3. Review masked results

    Display or export as JSON / CSV.

Implementation & limits
  • Pattern checks cover repeated chunks, sequences, keyboard walks and leetspeak-normalized dictionary words.
  • Online lookups send data to third parties: a SHA-1 prefix for password breach checks, the email for breach / disposable checks, and its domain for MX lookups.
  • Wordlist generation and OSINT features are intended only for authorized auditing.
  • JSON output, masked CSV, pip / pipx installation and an MIT license.

02 / Experimental tool · Linux service hardening

unitguard

From observed behavior to systemd sandbox settings. This Go CLI traces a locally executed process with strace, generates a systemd drop-in and checks that it covers the behavior captured in the trace.

Go · strace · systemd · MIT

Tested: build, go vet and tests across six packages on a fresh GitHub clone. A real trace-to-generation pipeline passed systemd-analyze syntax checks.

Experimental, not production-ready. Live-systemd apply and rollback are not yet validated; their state machine is mock-tested only. Syntax checks do not prove a service will tolerate the settings, and a trace can miss unexercised behavior. Do not use apply on a critical host or service.
